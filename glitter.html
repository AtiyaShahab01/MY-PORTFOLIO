Custom Features Case Study

Glitter.com — two custom features I built for this store: a personalized gift tool, and a booking system that stops double-bookings.

Feature 01

Make Your Own Gift

View Live Section →

The Requirement

The client wanted a product where customers could build their own gift box — writing a recipient's name ("To"), a short message, and their own name ("From") right onto the packaging, like a greeting card. Customers needed to see how their text would look before ordering, and that same information had to show up clearly in Shopify admin, so the packaging team knew exactly what to write on each box. And if a customer ordered a bundle of several boxes, each one needed its own separate message.

What I Did

1

Built a dedicated template

This product got its own template in Shopify, so the popup only shows up here — every other product on the store stays exactly the same.

2

Added a popup before Add to Cart

Instead of adding the product straight to cart, clicking "Add to Cart" opens a popup first — a preview of the gift box, with three fields below it: "To," "Message" (max 50 characters), and "From."

3

Made the preview update as you type

Whatever the customer types shows up inside the preview image instantly — no page reload needed — so they can see exactly how their message will look before ordering.

4

Saved the details with the order

Clicking "Continue" checks that all three fields are filled in. Once confirmed, "To," "Message," and "From" get attached to the product in the cart — so they appear automatically on the order in Shopify admin, word for word.

5

Made it work inside bundles too

When this product is part of a bundle, I hold the details in the browser first instead of sending them straight to the cart. Then, right before the bundle adds everything to cart, I step in and attach the correct "To / Message / From" to each box — so every box in the bundle keeps its own message.

Issues I Solved

Field name had to be changed everywhere

The "To" field started out labeled "Recipient's Name." When the client asked to shorten it to just "To," I had to update the name in two separate places in the code — the normal flow and the bundle flow — so the cart, checkout, and order page all matched.

Bundle app was deleting the message

The bundle app had its own way of preparing the cart data, and it would sometimes wipe out the message I'd added. I fixed this by letting the bundle app run first as normal, then adding my data right after — so it never gets deleted.

Result

Customers now see exactly what their message will look like before they buy, so they order with confidence. And every order , every product bundle carries clear "To / Message / From" details straight to Shopify admin, so the packaging team always knows what to write on each box.

Feature 02

Book Your Catering

View Live Section →

The Requirement

The client's catering service runs on real resources — a signature pink car, staff, and equipment — that can only be in one place at a time. Customers needed to pick at least 50 KWD worth of items (10–13 products) through the bundle app, then book a date and time for the catering to arrive: only within the next 30 days, and at least a day in advance. Most importantly, two customers could never be allowed to book the same date and time — otherwise the car and staff would need to be in two places at once.

The Problem

Shopify doesn't understand scheduling. It only tracks how many items are in stock — it has no idea what a "time slot" is. So if two customers picked the same date and time and checked out around the same moment, Shopify would accept both orders without a warning, leaving the client with two bookings that clash.

The Solution

I connected the store to Google Firebase — a real-time database that sits outside Shopify and works like a lock on each time slot. Every date and time combination gets its own entry, checked the moment a customer taps "Confirm Booking":

1

If that slot has never been booked, it gets marked "pending" with a 20-minute timer — a temporary hold so the customer has time to finish checkout before anyone else can take it.

2

If the slot is already confirmed, the customer sees an error right away: "Sorry, this date and time slot is already booked."

3

If someone else is checking out for that slot right now, the customer sees: "This slot is currently being booked by someone else."

4

If a hold's 20 minutes run out and no one completed checkout, the slot opens back up for the next customer.

On the popup itself, the date and time are picked with a date field and two radio buttons — a radio button only ever lets one option be selected, so a customer can only choose one date and one time slot per order. Once the booking is confirmed, those details are saved with the order, so they show up clearly on the admin order page.

Issues I Solved

Minimum order was being skipped

A different product ("Hair Clips") could be bought directly from search without meeting the 50 KWD minimum. The reason: it wasn't linked to any collection, so the minimum-order check never ran on it. I fixed this by marking it "Unlisted," so it's only reachable through the bundle.

Old dates showing up on iPhone

Reopening the popup on an iPhone sometimes showed outdated date limits. I fixed this by recalculating the allowed date range every time the popup opens, instead of setting it once when the page loads.

Old data coming back after pressing "Back"

On iPhone, pressing the browser's back button would sometimes bring back old, outdated bundle data instead of a fresh page. I fixed this by detecting when a page is restored from memory like that, and forcing it to reload fresh.

Result

Two customers can no longer book the same date and time — whoever confirms first gets it, and everyone else finds out right away that it's taken. This kind of scheduling conflict is something Shopify simply doesn't handle on its own, which is why an outside real-time database was the right fix.
